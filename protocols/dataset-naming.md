# 采集数据集命名

**状态：草案，待组内确认。** 数据目录里没有成文的命名规范。本文从现有名字归纳出现状，再给出一条建议。
现状部分是统计结果，建议部分是我起草的，没有人定过。

## 现状（统计自数据目录的 23 个顶层名字，不含 .zip 压缩包）

- 23 个目录名里，17 个以 `MMDD` 开头，日期范围 0904 到 0910。其中 `0908`、`0909` 只有日期，没有任务名。
- 6 个没有日期：`arx_pickplace`、`arx_stackcups`、`arx_t_expert_dagger_v1`、`fold_blue`、`handel_pickplace`、`pickplace_t_dagger_v1`。
  叠杯子和叠毛巾这两个最新的任务（`arx_stackcups`、`fold_blue`）正好是不带日期的。
- 日期之后的部分没有固定结构：有任务名（`pickandplace`、`yuanzhu`）、物体名（`blue`、`T`、`L`）、
  用途（`gripper_calibration`、`expert_dagger`、`mixed`）、序号（`01`、`02`、`_2`）和版本（`_v1`）混用。
- 版本后缀 `_v1` 出现 6 次，没有出现过 `_v2`。
- 大小写不统一：`0907_T`、`0907_blue_T` 用大写 T，`0907_blue_t_v1`、`arx_t_expert_dagger_v1`、`pickplace_t_dagger_v1` 用小写 t，从名字看不出是否同一类物体。
- 目录名里没有人名和中文。数据目录顶层还有 17 个 `.zip` 压缩包，其中的名字夹着人名缩写（`_lyf`、`_zbw`、`_hjs`、`_zypgyt`）和中文（`_已转换`），另有一个叫 `gripper校准` 的顶层目录也含中文。这些不在上面 23 个的统计里。
- 数据集目录里的子目录区分动作定义：`eef-vr`、`joint-vr`、`joint-feedback`，还有 `lerobot_v3_30fps_state_t_plus_1`
  这类写了格式、帧率和动作语义的长名。

这些名字不一致带来的实际问题：

1. 看目录名不知道这批数据是哪个任务、哪个采集方案、动作记录的是什么。
2. 同一批数据的不同动作定义（比如 0907 的三种）要靠子目录名区分，换个人命名就会错位。
3. 版本只有 `_v1`，没有规则说什么时候该升版本。

## 建议（草案）

```
<采集日期 MMDD>_<任务>[_<子集或批次>]
```

- **日期**：采集当天的 `MMDD`。拿不到确认的采集日期时，不要用文件日期冒充，在数据集记录的 `collected.date_basis` 里写明依据。
- **任务**：小写英文、下划线分隔，和采集命令里的 `INSTRUCTION` 对应得上，例如 `fold_blue`、`stack_cups`。
- **子集或批次**：同一任务同一天多批时加序号，两位数字，例如 `_01`、`_02`。
- **不放进名字的东西**：人名缩写、格式（`lerobot_v3_30fps`）、动作语义（`state_t_plus_1`）、是否转换过。这些写在数据集记录的字段里：
  `collected.by`、`format`、`action_semantics`、`variant`。
- **动作定义不同的衍生版本**：用子目录或 `variant` 区分，名字用 `eef-vr`、`joint-vr`、`joint-feedback` 这类现有写法，不在批次名里重复。
- **版本**：只有数据内容改变才升版本（重新标注、重新过滤、修了数据错误），写成 `_v2`。仅仅换了格式转换的，不是新版本，用 `variant`。

## 怎么处理现有名字

不改任何已有目录名，改名会让训练配置里写死的路径失效。新采集的数据按建议命名，已有的在数据集记录的 `notes` 里说明哪些不符合。
是否采用、怎么改，由组内决定后再更新本文。

## 数据集记录里和命名相关的字段

| 字段 | 含义 |
|---|---|
| `id` | 平台里的记录编号，`ds-` 开头，小写、数字、连字符。不等于目录名 |
| `batch_id` | 采集批次，同一批的不同版本归在一起。现在取自目录名里日期之后的第一段 |
| `variant` | 批次内的版本名，如 `eef-vr`、`subsets/first50` |
| `locations[].label` | 数据在哪台机器、哪个路径下。路径本身不放进公开页 |
